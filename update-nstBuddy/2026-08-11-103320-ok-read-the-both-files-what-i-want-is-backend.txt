     Wire nstBuddy frontend to the real backend, rebrand to green, replace meme 
     popup with an academic-integrity disclaimer

     Context

     update-nstBuddy/ (Vite + React 19 + TS + Tailwind v4) and backend/ (Express
     + Prisma/Postgres + Firebase Admin) already exist as separate,
     mostly-built pieces — this isn't a from-scratch build. The backend has real
     routes for campuses, questions, notices, auth, and contributions, and the
     frontend has real pages for campus → semester → question browsing,
     contribution, and Google/Firebase login. The problem is they're wired
     together inconsistently:

     - services/api.ts (the one shared axios client, with auth interceptor)
     points at http://localhost:5001/api, hardcoded.
     - Six other files (CampusSelection.tsx, SemesterSelection.tsx,
     Questions.tsx, ContributePage.tsx, AdminDashboard.tsx, services/auth.ts,
     services/courses.ts) each declare their own const API_URL = 
     'https://update-nstbuddy.onrender.com/api' and call axios directly,
     bypassing the shared client entirely.
     - The frontend .env already defines VITE_API_URL, but nothing reads it —
     every URL is hand-typed per file.

     Net effect: which backend a given page actually talks to depends on which
     file it is, not on any config. That's the opposite of "the website runs on
     this backend." Fixing it means consolidating on one configurable client.

     Two more things ride along with this pass, per your instructions:
     1. Rebrand the accent color from blue to green across the app (confirmed:
     full rebrand, not just a badge).
     2. Replace the meme popup (ExamPopup.tsx, currently shown to everyone on
     every page load) with an academic-integrity disclaimer that requires a
     click-through, is recorded per-user in the database, and re-prompts every 7
     days.

     Out of scope / flagging, not fixing: backend/src/routes/courses.js calls
     prisma.course.findMany(...), but there is no Course model in schema.prisma
     — that route (and services/courses.ts / the /courses nav link, which also
     doesn't have a matching route in App.tsx) is already dead/broken code
     unrelated to the Campus→Semester→Question flow you described. Leaving it
     alone rather than silently expanding scope; flag if you want it removed or
     fixed separately.

     ---
     Part A — Consolidate the frontend onto one configurable backend client

     Backend stays as-is for this part — it already exposes everything the
     frontend needs (/api/campuses, /api/campuses/:slug/semesters,
     /api/questions, /api/questions/filters, /api/questions/contribute,
     /api/contributions/leaderboard, /api/auth/verify-token, /api/notices).

     1. update-nstBuddy/src/services/api.ts: change the hardcoded base URL to
     const API_BASE_URL = import.meta.env.VITE_API_URL || 
     'http://localhost:5001/api';
     Add two missing resource groups to this file so every page can import from
     one place:
       - campusesApi: getAll() → GET /campuses, getSemesters(slug) → GET 
     /campuses/:slug/semesters.
       - contributionsApi: getLeaderboard(limit) → GET 
     /contributions/leaderboard.
       - questionsApi: add contribute(data) → POST /questions/contribute (the
     auth-required student endpoint, distinct from the existing admin-only
     create).
     2. services/auth.ts: drop its private API_URL/raw axios, reuse the api
     instance from services/api.ts instead (so it picks up the same base URL,
     interceptor, and credentials config). Add acknowledgeDisclaimer() here
     (Part C).
     3. Pages that currently hardcode the Render URL and call axios directly —
     CampusSelection.tsx, SemesterSelection.tsx, Questions.tsx,
     ContributePage.tsx, AdminDashboard.tsx, UserProfile.tsx (page) — delete
     their local const API_URL = ... and swap the raw axios.get/post calls for
     the corresponding questionsApi / campusesApi / contributionsApi calls from
     services/api.ts. This is a mechanical, per-file swap (same params, same
     response shape — nothing about the request itself changes, just where the
     base URL and auth header come from).
     4. services/courses.ts: leave using its own axios (it's already flagged as
     dead code above) — not worth wiring since the backend route it hits is
     broken.

     Result: exactly one place (VITE_API_URL in .env, already set to the
     deployed Render URL) controls which backend the entire site talks to.
     Pointing local dev at the local backend during testing is just a one-line
     .env change (or an untracked .env.local override), not a code change.

     ---
     Part B — Green rebrand

     No CSS theme tokens exist today (index.css is just @import "tailwindcss" +
     a font rule) — every accent color is a literal Tailwind utility class
     (bg-blue-600, text-blue-600, border-blue-500, ring-blue-500, etc.) repeated
     across ~19 files (CampusSelection.tsx, AdminDashboard.tsx, Footer.tsx,
     ContributePage.tsx, AIUploadPopup.tsx, Questions.tsx, Navbar.tsx,
     UserProfile.tsx (page + component), ExtensionInstall.tsx,
     SemesterSelection.tsx, Login.tsx, Home.tsx, AuthContext.tsx,
     NoticeBoard.tsx, LoadingSpinner.tsx, ProtectedRoute.tsx,
     AssignmentCard.tsx).

     Approach: systematic blue-{shade} → emerald-{shade} replacement across
     update-nstBuddy/src/**/*.tsx (emerald rather than plain green because a few
     emerald accents already exist alongside blue in the current design — e.g.
     the "Active community" dot, "Question Solved" check — so this keeps one
     consistent green family instead of two). This covers buttons, links,
     active-nav underlines, focus rings, spinners, and the Navbar's "2.0"
     badge/notification dot. Gradients that pair blue with purple/indigo (e.g.
     Login page background, Discord banner) get their blue stop swapped to
     emerald too, keeping the second color as-is so they don't turn into a flat
     single-color gradient.

     I'll do this as a targeted find-and-replace pass per file (not a blind
     global sed, since a couple of files use blue- as part of unrelated words) —
     reusing the same class-name swap per file.

     Part C — Replace the meme popup with an academic-integrity disclaimer

     Current state: components/layout/ExamPopup.tsx shows a meme image + "Brace
     Yourself!" message to every visitor on every load (mounted in App.tsx
     outside the route tree, inside AuthProvider), dismissible via a close
     button, nothing persisted.

     New behavior: a non-dismissable (no close-X — only the acknowledgement
     button) modal shown to logged-in users the first time they arrive, and
     again after any 7-day gap since their last acknowledgement, whose click is
     recorded server-side against their user record.

     3. routes/auth.js:

     /verify-token (so the frontend knows on login/refresh, no extra
     round-trip).
       - New route POST /auth/acknowledge-disclaimer, behind authenticateUser
     (existing middleware in middleware/auth.js), setting
     disclaimerAcknowledgedAt: new Date() on req.user's row and returning the
     updated timestamp.

     Frontend

     1. contexts/AuthContext.tsx: add disclaimerAcknowledgedAt: string | null to
     the User interface; it flows through automatically since user is already
     set from verifyToken's response.
     2. services/auth.ts: add acknowledgeDisclaimer(idToken) → POST 
     /auth/acknowledge-disclaimer with Authorization: Bearer <idToken>.
     3. Replace components/layout/ExamPopup.tsx with

       - Reads user from useAuth(). Computes shouldShow = user &&
